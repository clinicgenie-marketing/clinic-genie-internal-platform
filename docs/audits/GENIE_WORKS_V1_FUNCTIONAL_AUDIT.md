## B. V1 readiness
**Verdict: NOT READY FOR VERSION 1.** Mandatory Blog is wholly absent, several required Agency Overview/Leads/Settings/Admin functions are missing, Reports lacks website/status/approval semantics, and live integration paths are unconfirmed or configuration-blocked.

- Total register checks: **145**.
- Status counts: **8 VERIFIED COMPLETE**, **64 PARTIAL**, **53 MISSING**, **1 BROKEN**, **19 UNVERIFIED**.
- Scope counts: **123 mandatory**, **6 explicitly deferred**, **5 conditional**, **11 ambiguous**.
- Mandatory verified-completion: **7/123 = 5.7%**. This strict numerator counts only requirement checks with successful relevant runtime evidence; PARTIAL and UNVERIFIED do not count.
- Blog mandatory checks are included in the mandatory denominator. Blog Performance checks are explicitly deferred and excluded. Conditional and ambiguous checks are reported separately and excluded from that denominator.
- Denominator caution: checks are split for verifiability from the source’s combined clauses; this is a functional audit measure, not an estimate of engineering effort.

Runtime/build results:
- `npm run typecheck`: passed.
- `npm run lint`: passed with 10 warnings, 0 errors.
- `npm run build`: passed with five dynamic-filesystem tracing warnings.
- `npx playwright test`: 2/2 passed.
- `npm test`: failed overall: DB 41/42 passed; one deactivated-member test failed because a direct update was rejected by the admin-only trigger. Platform Vitest then reported no test files and exit code 1.
- Browser: all nine module routes returned a page after authentication; `/blog` returned HTTP 200 but had no heading or content. Profile-name persistence survived reload and was restored. A no-membership read-only account was redirected away from Admin and a known client, and analytics export returned 403.
- Reproduced defect: a specialist-visible website edit is filtered to zero rows by global-only RLS, while the service/action returns a success message; the change does not persist.
- Cross-cutting defect: hardcoded fire-and-forget debug requests remain in `apps/platform/src/lib/auth.ts`, `apps/platform/src/lib/session.ts` and `packages/db/src/client.ts`, including authentication outcome/domain and database connection metadata.
